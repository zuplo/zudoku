Version 2 of the Shipment API is live. It is fully backwards compatible: existing integrations keep
working, and you can adopt the new features one at a time.

## Webhooks for every status change

Subscribe once and receive a signed event whenever a shipment changes state, from `booked` to
`delivered`. No more polling the events endpoint.

## Idempotent bookings

Send an `Idempotency-Key` header with `POST /shipments` and retries after a dropped subspace link
will never book the same cargo twice.
